Everything the v1 trainer web app reads or writes. The tenancy tables stay in v1 although workspaces do not ship: every row's tenant_id and every row-level security policy depend on them, and each trainer gets one solo workspace by trigger.

Conventions that hold on every table
primary-key
Every table has id uuid PRIMARY KEY DEFAULT gen_random_uuid(). Ids are normally generated client-side (UUID v4); the default is a fallback.
ownership
Trainer-scoped tables carry trainer_id and every query filters on it, so a wrong id answers 404, not 403.
soft-delete
deleted_at NULL means alive. Nothing is hard-deleted; every read filters deleted_at IS NULL. Log tables (otp_request, client_assignment, team_activity) have no deleted_at — a mistake is corrected by writing another row. Since V21 the request role holds no DELETE except on attention_dismissal, web_session and otp_request, and no UPDATE on the three logs.
erasure
Deleting an account is an erasure (P2), not a soft delete. erase_account() sets the personal columns of app_user, trainer and client to NULL under a CHECK that lists them, so the rows stay as tombstones, and the phone number is released. purge_tenant() is the one hard delete: it empties a closed workspace once purge_after has passed. What survives is erasure_log, which holds counts only, and nameless amounts and dates in workspaces the person did not own.
updated-at
updated_at is maintained by the set_updated_at() trigger on every table that has it, and is the sync cursor. Since V21 there is no exception: working_hours, time_block and batch used to take the device's own value on sync push, which a wrong clock turned into an edit no other device ever pulled.
tenant-id
tenant_id is the workspace a row belongs to. It is stamped on insert by stamp_tenant_id(), refused any change by freeze_tenant_id(), and row-level security filters on it.
money
Money is numeric(10,2), currency varchar(3) defaulting to INR, percentages numeric(5,2).
enumerations
Enumerated columns are plain varchar, never a Postgres ENUM. Vocabularies (profile lists, nudge kinds, payment.method) are validated in application code; since V21 state machines and money columns also carry a CHECK, so a new state is a code change plus one DROP / ADD CONSTRAINT in a migration. Legal values are listed per column under allowedValues.
foreign-keys
Unless stated otherwise a foreign key is ON UPDATE NO ACTION, ON DELETE NO ACTION — rows are soft-deleted, so nothing cascades.

CREATE FUNCTION public.respond_tenant_invite(invite uuid, accept boolean) RETURNS uuid
    LANGUAGE plpgsql SECURITY DEFINER
    SET search_path TO 'public', 'pg_catalog'
    AS $$
DECLARE
    inv    tenant_invite;
    me     uuid;
    member uuid;
BEGIN
    SELECT * INTO inv FROM tenant_invite WHERE id = invite FOR UPDATE;

    SELECT au.id INTO me FROM app_user au
     WHERE au.id = app_user_id() AND au.phone = inv.phone AND au.deleted_at IS NULL;

    IF inv.id IS NULL OR me IS NULL OR app_actor() <> 'staff' THEN
        RAISE EXCEPTION 'no such invitation' USING ERRCODE = 'no_data_found';
    END IF;
    IF inv.status <> 'pending' OR inv.expires_at <= now() THEN
        RAISE EXCEPTION 'this invitation is no longer open' USING ERRCODE = 'check_violation';
    END IF;

    IF NOT accept THEN
        UPDATE tenant_invite SET status = 'declined', responded_at = now() WHERE id = inv.id;
        RETURN NULL;
    END IF;

    INSERT INTO tenant_member (tenant_id, tenant_type, app_user_id, role, status, invited_by_member_id)
    VALUES (inv.tenant_id, inv.tenant_type, me, inv.role, 'active', inv.invited_by_member_id)
    ON CONFLICT (tenant_id, app_user_id, role) WHERE deleted_at IS NULL
    DO UPDATE SET status = 'active', ended_at = NULL, joined_at = now(),
                  invited_by_member_id = EXCLUDED.invited_by_member_id
        WHERE tenant_member.status = 'removed'
    RETURNING id INTO member;

    -- A live row the conflict did not update: they are already a member.
    IF member IS NULL THEN
        RAISE EXCEPTION 'already a member of this workspace' USING ERRCODE = 'unique_violation';
    END IF;

    UPDATE tenant_invite
       SET status = 'accepted', responded_at = now(), member_id = member
     WHERE id = inv.id;
    RETURN member;
END $$;

P2Deleting an account is an erasure: the person's data goes, the ledgers keep only counts agreed · 2026-09-24

DELETE /v1/trainers/me (and, when the portal ships, a client's own account delete) stops being a soft delete and becomes erase_account(), one transaction: (1) the person's **solo workspace is closed** and emptied by the purge job; (2) they are **removed from every other workspace**; (3) a **team or gym they own blocks the delete** until they hand it on with transfer_tenant_ownership(). Support can instead pass leave_owned, which leaves that workspace with no owner until support assigns one. (5) The app_user, trainer and client rows stay as **tombstones**: an id and dates, with the personal columns NULL, and a CHECK that makes an incomplete scrub unwritable. The phone number is **released**. What stays is audit without identity: erasure_log (what was erased, when, row counts), subscription (our billing), privacy_accepted_at (consent evidence), and, in workspaces the person did not own, sessions and payments as amounts and dates against a client or coach who has no name. Workspace delete — the other case — reuses purge_after / purged_at and is a later proposal.

adderase_account(uuid, boolean)

The only way an account ends. Called by the request role for oneself (target = app_user_id()); called by an operator for anyone, and only an operator may pass leave_owned. Refuses with OWNS_WORKSPACE while the person owns a live team or gym. Solo workspaces are closed and their clients erased at once; clients they coach in other workspaces stay there flagged stale_reason = 'trainer_left'. All their memberships end, invitations to their number are deleted, sessions are revoked, and wherever they are a client that row is erased. Last, trainer and app_user become tombstones. One transaction: an erasure is never half done. Callers cancel the UPI Autopay mandate with the provider first, since the function can only mark subscription cancelled.

SQL
CREATE FUNCTION public.erase_account(target uuid, leave_owned boolean DEFAULT false) RETURNS uuid
    LANGUAGE plpgsql SECURITY DEFINER
    SET search_path TO 'public', 'pg_catalog'
    AS $$
DECLARE
    u       app_user;
    tr      trainer;
    by_self boolean := session_user = 'inclineyou_app';
    via     varchar := CASE WHEN session_user = 'inclineyou_app' THEN 'self' ELSE 'support' END;
    log_id  uuid;
    solo    uuid[];
    cids    uuid[];
BEGIN
    SELECT * INTO u FROM app_user WHERE id = target AND erased_at IS NULL FOR UPDATE;
    IF u.id IS NULL OR (by_self AND target IS DISTINCT FROM app_user_id()) THEN
        RAISE EXCEPTION 'no such account' USING ERRCODE = 'no_data_found';
    END IF;
    IF by_self AND leave_owned THEN
        RAISE EXCEPTION 'only support can leave a workspace without an owner'
            USING ERRCODE = 'insufficient_privilege';
    END IF;

    -- A team or gym they own is other people's workplace. It gets a new owner
    -- first (transfer_tenant_ownership), or support passes leave_owned.
    IF NOT leave_owned AND EXISTS (
        SELECT 1 FROM tenant_member m JOIN tenant t ON t.id = m.tenant_id
         WHERE m.app_user_id = target AND m.role = 'owner'
           AND m.status = 'active' AND m.deleted_at IS NULL
           AND t.type <> 'solo' AND t.status <> 'closed') THEN
        RAISE EXCEPTION 'OWNS_WORKSPACE' USING ERRCODE = 'check_violation';
    END IF;

    SELECT * INTO tr FROM trainer WHERE phone = u.phone AND erased_at IS NULL FOR UPDATE;

    INSERT INTO erasure_log (kind, app_user_id, requested_by)
    VALUES ('account', target, via) RETURNING id INTO log_id;

    -- 1. Their own solo workspace: closed now, emptied by purge_closed_tenants().
    SELECT COALESCE(array_agg(t.id), '{}') INTO solo
      FROM tenant t
     WHERE t.type = 'solo' AND t.status <> 'closed'
       AND (t.id = tr.home_tenant_id
            OR EXISTS (SELECT 1 FROM tenant_member m
                        WHERE m.tenant_id = t.id AND m.app_user_id = target
                          AND m.role = 'owner' AND m.deleted_at IS NULL));

    UPDATE tenant SET status = 'closed', name = 'Closed workspace', metadata = '{}', purge_after = now()
     WHERE id = ANY (solo);
    INSERT INTO erasure_log (kind, parent_id, tenant_id, requested_by)
    SELECT 'workspace', log_id, s, via FROM unnest(solo) s;

    SELECT COALESCE(array_agg(id), '{}') INTO cids
      FROM client WHERE tenant_id = ANY (solo) AND erased_at IS NULL;
    PERFORM erase_clients(cids);

    -- 2. As a coach in somebody else's workspace: that workspace keeps its
    --    clients and their history, flagged for a new coach. Only bookings
    --    that have not happened yet are withdrawn.
    IF tr.id IS NOT NULL THEN
        UPDATE client SET stale_at = now(), stale_reason = 'trainer_left'
         WHERE trainer_id = tr.id AND NOT (tenant_id = ANY (solo))
           AND deleted_at IS NULL AND stale_at IS NULL;
        UPDATE scheduled_session SET deleted_at = now()
         WHERE trainer_id = tr.id AND NOT (tenant_id = ANY (solo))
           AND scheduled_at > now() AND deleted_at IS NULL;
        DELETE FROM trainer_notification WHERE trainer_id = tr.id;
        UPDATE subscription SET state = 'cancelled', cancelled_at = COALESCE(cancelled_at, now())
         WHERE trainer_id = tr.id;
    END IF;

    -- 3. Every membership ends, owned ones included. deleted_at as well as
    --    removed, so the partial unique indexes stop counting the rows and an
    --    ownerless workspace can take a new owner.
    UPDATE tenant_member_terms mt
       SET effective_to = GREATEST(current_date, mt.effective_from + 1)
      FROM tenant_member m
     WHERE mt.tenant_member_id = m.id AND m.app_user_id = target AND mt.effective_to IS NULL;
    UPDATE tenant_member
       SET status = 'removed', ended_at = COALESCE(ended_at, now()), is_home = false, deleted_at = now()
     WHERE app_user_id = target AND deleted_at IS NULL;
    IF tr.id IS NOT NULL THEN
        UPDATE team_member SET status = 'removed', invited_phone = NULL, deleted_at = now()
         WHERE trainer_id = tr.id AND deleted_at IS NULL;
    END IF;

    -- 4. Everything addressed to the number.
    DELETE FROM team_member   WHERE invited_phone = u.phone AND trainer_id IS NULL;
    DELETE FROM tenant_invite WHERE phone = u.phone;
    DELETE FROM web_session   WHERE app_user_id = target OR phone = u.phone;
    DELETE FROM otp_request   WHERE phone = u.phone;

    -- 5. Wherever they are somebody's client.
    SELECT COALESCE(array_agg(id), '{}') INTO cids
      FROM client WHERE phone = u.phone AND erased_at IS NULL;
    PERFORM erase_clients(cids);

    -- 6. The identity. Ids stay, so every foreign key still resolves.
    IF tr.id IS NOT NULL THEN
        UPDATE trainer
           SET erased_at = now(), deleted_at = COALESCE(deleted_at, now()),
               phone = NULL, name = NULL, email = NULL, upi_vpa = NULL, fcm_token = NULL,
               headline = NULL, bio = NULL, intro_video_url = NULL, map_link = NULL,
               instagram_url = NULL, youtube_url = NULL, gym_name = NULL, gender = NULL,
               experience_band = NULL, specialities = '[]', certifications = '[]',
               languages = '[]', training_modes = '[]', service_areas = '[]', metadata = '{}'
         WHERE id = tr.id;
    END IF;
    UPDATE app_user SET phone = NULL, erased_at = now(), deleted_at = COALESCE(deleted_at, now())
     WHERE id = target;

    UPDATE erasure_log SET completed_at = now() WHERE id = log_id;
    RETURN log_id;
END $$;

Erases client rows, shared by both callers in erase_account(). CREATE FUNCTION public.erase_clients(ids uuid[]) RETURNS integer
    LANGUAGE plpgsql SECURITY DEFINER
    SET search_path TO 'public', 'pg_catalog'
    AS $$
DECLARE
    n integer;
BEGIN
    IF cardinality(ids) = 0 THEN
        RETURN 0;
    END IF;

    -- Everything that is about the person rather than a count in a ledger.
    DELETE FROM client_prefs         WHERE client_id = ANY (ids);
    DELETE FROM client_notification  WHERE client_id = ANY (ids);
    DELETE FROM client_message       WHERE client_id = ANY (ids);
    DELETE FROM workout_feedback     WHERE client_id = ANY (ids);
    DELETE FROM milestone            WHERE client_id = ANY (ids);
    DELETE FROM assessment           WHERE client_id = ANY (ids);
    DELETE FROM client_note          WHERE client_id = ANY (ids);
    DELETE FROM weekly_report        WHERE client_id = ANY (ids);
    DELETE FROM attention_dismissal  WHERE client_id = ANY (ids);
    DELETE FROM trainer_notification WHERE client_id = ANY (ids);
    DELETE FROM nudge_log            WHERE client_id = ANY (ids);
    DELETE FROM team_activity        WHERE client_id = ANY (ids);
    UPDATE client_assignment SET note = NULL WHERE client_id = ANY (ids) AND note IS NOT NULL;

    -- Bookings that have not happened are nobody's any more.
    DELETE FROM scheduled_session s
     WHERE s.client_id = ANY (ids) AND s.scheduled_at > now()
       AND NOT EXISTS (SELECT 1 FROM workout_session w WHERE w.scheduled_session_id = s.id);

    -- The plan goes; what was logged against it stays, unlinked and without free text.
    UPDATE workout_session   SET program_id = NULL, notes = NULL WHERE client_id = ANY (ids);
    UPDATE scheduled_session SET program_id = NULL, notes = NULL WHERE client_id = ANY (ids);
    UPDATE set_log sl SET notes = NULL
      FROM workout_session w
     WHERE sl.workout_session_id = w.id AND w.client_id = ANY (ids) AND sl.notes IS NOT NULL;
    DELETE FROM program_exercise pe USING program p
     WHERE pe.program_id = p.id AND p.client_id = ANY (ids);
    DELETE FROM program WHERE client_id = ANY (ids);

    -- The money stays as amounts, dates and receipt numbers.
    UPDATE payment SET note = NULL WHERE client_id = ANY (ids) AND note IS NOT NULL;

      FROM package pk
     WHERE pa.package_id = pk.id AND pk.client_id = ANY (ids) AND pa.reason IS NOT NULL;

    UPDATE client
       SET erased_at = now(), deleted_at = COALESCE(deleted_at, now()),
           name = NULL, phone = NULL, goal = NULL, metadata = NULL, height_cm = NULL,
           activity_level = NULL, date_of_birth = NULL, weekly_schedule = NULL
     WHERE id = ANY (ids);
    GET DIAGNOSTICS n = ROW_COUNT;
    RETURN n;
END $$;
addtransfer_tenant_ownership(uuid, uuid)

Hands a team or gym to one of its live members: the owner, or support for a workspace left ownerless. The old owner row ends (removed + deleted_at), and their home moves if it was there. A new owner row is written, which is the only way one is ever inserted after creation (refuse_owner_promotion() still stops a request-role UPDATE from making one). A team also moves team.owner_trainer_id, so the new owner must be a trainer.

SQL
CREATE FUNCTION public.transfer_tenant_ownership(target uuid, to_user uuid) RETURNS uuid
    LANGUAGE plpgsql SECURITY DEFINER
    SET search_path TO 'public', 'pg_catalog'
    AS $$
DECLARE
    t          tenant;
    old_member uuid;
    old_home   boolean;
    old_user   uuid;
    owner      uuid;
    coach      uuid;
BEGIN
    SELECT * INTO t FROM tenant WHERE id = target AND status <> 'closed' FOR UPDATE;
    IF t.id IS NULL OR t.type = 'solo' THEN
        RAISE EXCEPTION 'no such workspace' USING ERRCODE = 'no_data_found';
    END IF;
    -- The owner hands it on; support can hand on one that has no owner left.
    IF session_user = 'inclineyou_app' AND NOT app_owns_tenant(target) THEN
        RAISE EXCEPTION 'only the owner can transfer a workspace' USING ERRCODE = 'insufficient_privilege';
    END IF;
    IF NOT EXISTS (
        SELECT 1 FROM tenant_member m JOIN app_user au ON au.id = m.app_user_id
         WHERE m.tenant_id = target AND m.app_user_id = to_user AND m.role <> 'owner'
           AND m.status = 'active' AND m.deleted_at IS NULL
           AND au.deleted_at IS NULL) THEN
        RAISE EXCEPTION 'the new owner must be a member of this workspace' USING ERRCODE = 'check_violation';
    END IF;
    IF t.type = 'team' THEN
        SELECT tr.id INTO coach FROM trainer tr JOIN app_user au ON au.phone = tr.phone
         WHERE au.id = to_user AND tr.deleted_at IS NULL;
        IF coach IS NULL THEN
            RAISE EXCEPTION 'a team owner must be a trainer' USING ERRCODE = 'check_violation';
        END IF;
    END IF;

    SELECT id, app_user_id, is_home INTO old_member, old_user, old_home
      FROM tenant_member
     WHERE tenant_id = target AND role = 'owner' AND deleted_at IS NULL
       FOR UPDATE;
    UPDATE tenant_member
       SET status = 'removed', ended_at = now(), is_home = false, deleted_at = now()
     WHERE tenant_id = target AND role = 'owner' AND deleted_at IS NULL;

    -- The old owner's home moves to a membership they still hold.
    IF old_home THEN
        UPDATE tenant_member SET is_home = true
         WHERE id = (SELECT id FROM tenant_member
                      WHERE app_user_id = old_user AND status = 'active' AND deleted_at IS NULL
                      ORDER BY (tenant_type = 'solo') DESC, joined_at LIMIT 1);
    END IF;

    -- Handed on by the old owner's membership; NULL when support fills a
    -- workspace that had none left, which nobody in it did.
    INSERT INTO tenant_member (tenant_id, tenant_type, app_user_id, role, status, invited_by_member_id)
    VALUES (target, t.type, to_user, 'owner', 'active', old_member)
    RETURNING id INTO owner;

    IF t.type = 'team' THEN
        UPDATE team SET owner_trainer_id = coach WHERE tenant_id = target;
    END IF;
    RETURN owner;
END $$;
addpurge_tenant(uuid)

Hard-deletes every row a closed, due workspace holds, children first, and returns the counts. The one hard delete in the schema. Library rows (exercise, template, pack, batch) still used by another workspace are kept: they name no person, and deleting them would break that workspace's plans. Not granted: reached only through the job.

SQL
CREATE FUNCTION public.purge_tenant(target uuid) RETURNS jsonb
    LANGUAGE plpgsql SECURITY DEFINER
    SET search_path TO 'public', 'pg_catalog'
    AS $$
DECLARE
    counts jsonb := '{}';
    tbl    text;
    n      bigint;
BEGIN
    IF NOT EXISTS (SELECT 1 FROM tenant WHERE id = target AND status = 'closed'
                      AND purge_after <= now() AND purged_at IS NULL) THEN
        RAISE EXCEPTION 'workspace % is not due for purge', target USING ERRCODE = 'check_violation';
    END IF;

    -- Children before parents: every foreign key here is NO ACTION.
    FOREACH tbl IN ARRAY ARRAY[
        'set_log', 'workout_exercise', 'workout_feedback', 'workout_session',
        'scheduled_session', 'program_exercise', 'program',
        'payment', 'package_adjustment', 'package',
        'assessment', 'client_note', 'client_message', 'milestone', 'client_prefs',
        'client_notification', 'trainer_notification', 'nudge_log', 'weekly_report',
        'attention_dismissal', 'client_assignment', 'team_activity', 'client',
        'exercise_favourite', 'workout_template', 'assessment_template',
        'working_hours', 'time_block', 'nudge_rule', 'nudge_template', 'gym_settlement',
        'team_member', 'team', 'gym_branch', 'gym',
        'tenant_member_terms', 'tenant_invite', 'tenant_member', 'web_session']
    LOOP
        EXECUTE format('DELETE FROM %I WHERE tenant_id = $1', tbl) USING target;
        GET DIAGNOSTICS n = ROW_COUNT;
        IF n > 0 THEN counts := counts || jsonb_build_object(tbl, n); END IF;
    END LOOP;

    -- Library rows another workspace still uses are kept: they carry no
    -- personal data, and deleting them would break that workspace's plans.
    DELETE FROM batch b WHERE b.tenant_id = target
       AND NOT EXISTS (SELECT 1 FROM scheduled_session s WHERE s.batch_id = b.id);
    GET DIAGNOSTICS n = ROW_COUNT;
    IF n > 0 THEN counts := counts || jsonb_build_object('batch', n); END IF;

    DELETE FROM exercise e WHERE e.tenant_id = target
       AND NOT EXISTS (SELECT 1 FROM program_exercise x WHERE e.id IN (x.exercise_id, x.alt_exercise_id))
       AND NOT EXISTS (SELECT 1 FROM workout_exercise x WHERE e.id IN (x.exercise_id, x.swapped_from_exercise_id))
       AND NOT EXISTS (SELECT 1 FROM set_log x WHERE x.exercise_id = e.id)
       AND NOT EXISTS (SELECT 1 FROM exercise_favourite x WHERE x.exercise_id = e.id);
    GET DIAGNOSTICS n = ROW_COUNT;
    IF n > 0 THEN counts := counts || jsonb_build_object('exercise', n); END IF;

    DELETE FROM template t WHERE t.tenant_id = target
       AND NOT EXISTS (SELECT 1 FROM program p WHERE p.template_id = t.id);
    GET DIAGNOSTICS n = ROW_COUNT;
    IF n > 0 THEN counts := counts || jsonb_build_object('template', n); END IF;

    DELETE FROM pack k WHERE k.tenant_id = target
       AND NOT EXISTS (SELECT 1 FROM package p WHERE p.pack_id = k.id);
    GET DIAGNOSTICS n = ROW_COUNT;
    IF n > 0 THEN counts := counts || jsonb_build_object('pack', n); END IF;

    UPDATE tenant SET purged_at = now() WHERE id = target;
    RETURN counts;
END $$;
addpurge_closed_tenants(integer)

The job, run on a schedule by the backend. Purges up to batch_size due workspaces, oldest first, SKIP LOCKED so two instances never race, and completes their erasure_log rows.

SQL
CREATE FUNCTION public.purge_closed_tenants(batch_size integer DEFAULT 20) RETURNS integer
    LANGUAGE plpgsql SECURITY DEFINER
    SET search_path TO 'public', 'pg_catalog'
    AS $$
DECLARE
    t    uuid;
    c    jsonb;
    done integer := 0;
BEGIN
    FOR t IN SELECT id FROM tenant
              WHERE status = 'closed' AND purge_after <= now() AND purged_at IS NULL
              ORDER BY purge_after
              LIMIT batch_size
              FOR UPDATE SKIP LOCKED
    LOOP
        c := purge_tenant(t);
        UPDATE erasure_log SET completed_at = now(), row_counts = c
         WHERE kind = 'workspace' AND tenant_id = t AND completed_at IS NULL;
        done := done + 1;
    END LOOP;
    RETURN done;
END $$;
