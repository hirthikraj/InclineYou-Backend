Actions — the four ways a trainer tells the product to do something

Four components, and the boundaries between them are the useful part: a button changes data, a link changes place, a button group changes how you are looking at the same data, and an icon button is a button that has earned the right to drop its label. Getting these confused is the most common structural mistake in a ported mobile design.

Button

Stable

A button performs an action here and now. It is the only control in the system allowed to change data, and the label must say what the change is — Record payment, not Submit.

Do and don’t

guidelines

Do

One primary, one quiet escape. The eye finds the action in a single fixation, and Cancel earns no emphasis because nothing is at stake in leaving.

Don’t

Two primaries and a bordered cancel. The trainer now has to read three labels to find out which one the panel was for.

Do

Destructive actions name what they destroy, and are the only red thing on screen. Red used for anything else spends the alarm.

Don’t

Red on a non-destructive action. After the second time a trainer sees this, red stops meaning anything and the real one gets clicked.

Accessibility

ConcernHow it is handled
ElementAlways a real <button type="button">. A styled <div> is not focusable and does not fire on Space.
Accessible nameThe visible label. If an icon carries meaning the label still states it — the icon is never the only name.
KeyboardTab to reach, Enter or Space to activate. No custom key handling.
Focus:focus-visible only, so a pointer click does not draw a ring while a keyboard tab always does.
Disabledaria-disabled="true" rather than the disabled attribute, so the control stays focusable and a screen reader can still read why it is unavailable. The click handler no-ops.
ContrastPrimary 15.2:1, secondary 7.9:1, ghost 7.9:1, danger 4.9:1. Disabled is exempt from SC 1.4.3 but still measures 2.8:1, which is legible enough to read.
Target size34×34 minimum, 28px high for .btn--sm plus 4px of invisible slop, so every button clears 24×24.

Do and don’t

guidelines

Do

One icon button at the end of a row, holding everything that is not the row’s primary action. Overflow is a place, not a decision.

Don’t

Five glyphs and no words. A trainer cannot tell the rupee from the chart at a glance, so every row becomes a guessing game with money in it.

Accessibility

ConcernHow it is handled
Accessible namearia-label is mandatory. An icon button with no label is announced as “button” and is unusable.
Sighted hintA title for the pointer. The label and the title say the same words, so nobody gets two different names for one control.
Never icon-only for destructiveA trash glyph alone is a mis-click waiting to happen. Destructive icon buttons still open a confirm that names the object.
ContrastGlyph is --tx-ink-2 at 7.9:1 — comfortably over the 3:1 that SC 1.4.11 asks of a meaningful graphic.

Button group

Stable

Two to four mutually exclusive views of the same data, shown as one welded control. It changes how you look, never what is there — that distinction is what separates it from tabs and from a filter chip.

Do and don’t

guidelines

Do

Three short nouns, one always selected. A trainer can see every option and the current one without opening anything.

Don’t

Five long labels. The control is now wider than the toolbar it sits in, and the labels repeat the same word three times.

Accessibility

ConcernHow it is handled
PatternButtons with aria-pressed, not radios. The group is not a form value; it is a view preference that lives in the URL.
KeyboardTab reaches the group, then ← → move between segments and Enter commits — the roving-tabindex pattern, so the group is one stop rather than four.
Never zero-selectedExactly one segment is always pressed. An empty group leaves the reader unable to tell what they are looking at.
ContrastSelected 17.0:1 on --tx-surface-3, unselected 7.9:1.

Inline link

Stable

A link goes somewhere. In this product that means a client, a session, a report or a route — and because every one of those has a URL, the link is a real <a href> that can be middle-clicked, copied and opened in a new tab.

Accessibility

ConcernHow it is handled
ElementButtons do things, links go places. A link that runs an action breaks middle-click and the back button, both of which a desktop user will try.
NameThe link text says the destination. No “click here”, and no bare “view” repeated down a column — twenty identical link names in a screen-reader list is useless.
UnderlineColour is never the only signal in prose: the accent measures 6.1:1 on light, which passes text contrast but not the 3:1 SC 1.4.1 asks between the link and the surrounding text.
New tabNever forced. A trainer who wants a new tab uses their own modifier key.
