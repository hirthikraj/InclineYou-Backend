SUPERSEDED · 23 Aug 2026 — the web app is ONLINE-ONLY

This page was written offline-first. That decision has been reversed for the web: the web app writes every response straight to the server — no browser storage, no write queue, no sync. Offline-first remains the architecture of the phone (app/) and of nothing else.

So wherever this page draws or argues for an offline banner, a synced / queued pill, a “held on this device” count, or the sync-queue screen, that chrome is not built on the web. The reasoning around it is kept, because the rest of each finding depends on it — only the offline half is void.

Authority: CLAUDE.md at the repo root, and web app/web/AGENTS.md. Do not re-derive the offline behaviour from this page.

The rule that decides everything

#C6F24E measures 1.17:1 on --tx-surface-2 in light theme and 1.3:1 on white. It is a fill colour — never a stroke, never text on a light ground. On light it steps to --tx-accent-text (#4F6B0A, 6.1:1). Lime at full strength survives on light only as a field with #0A0B0D knocked out of it (15.2:1). This rule has caused four real bugs in this project, so it is stated first.

It has one web-specific consequence: the current rail item is not a filled lime row. A filled row would put 13.5px text on lime — legal on dark, illegal the moment anyone builds the light theme. It is a lime bar plus lime text on a 12% wash instead.

05Density — what changed, and the measurement

List row56px--w-row 44px Twelve rows on screen instead of four and a half. A mouse does not need a thumb’s target.
Two-line row72px--w-row-lg 56px Same reasoning; the second line is 12px, not 13.5px.
Control floor--tx-tap-min 48px --w-tap 32px WCAG 2.2 SC 2.5.8 asks 24×24 CSS px for a pointer. 32 is comfortably clear of it.

06The eight layout patterns

Every screen in this system is one of these eight, or two of them nested one level. If a design needs a ninth, that is a signal the screen is doing two jobs.

PatternUse it whenApp equivalent Rules
List–detail splitA set of things you pick from and then read A list screen + a push List pane 400px fixed. Selection lives in the URL. J/K moves, Enter opens.
Data tableRows you compare, sort or select in bulk A card list Sticky head. Money right-aligned and tabular. One line per cell unless .wrap.
Right panelCreate or edit something while its context stays visible Bottom sheet 420px, or 520px for a grid inside. Esc closes. Never stacks two deep.
ModalA destructive confirm, or two fieldsDialog 472px. Must answer “what happens to the money” and “can I undo this”.
Command paletteFind anything, run anything— ⌘K. Actions are scoped to the current match, not global.
Calendar gridTime across a weekDay list + month grid Colour by domain only. A non-working hour is hatched, not empty.
Builder gridTwo axes and a value in the cell Nested pushes Tab moves across the week, not down the exercise. ⌘Z mandatory.
Bulk barRows are selected— Replaces the toolbar in place; never floats over content that was readable.

Why this section is a link and not a gallery

It used to be a gallery: every control in one 1440×900 frame inside a browser window. That answers exactly one question — does the density hold together — and it is a fair question, which is why the density table in §05 above still exists. But a wall of controls cannot say what a component’s states are, what its parts are called, when to use it instead of the next one, or what its accessible name should be. Those are the questions a handoff actually gets asked, so each component now has a page.

09What is deliberately not here

Not builtWhy
A light theme gallery The tokens exist and are complete, so light works. It is not drawn because the product ships dark-default and a light screenshot in a review file invites someone to design for it before it is a decision. Use the toggle in the top bar to check any frame.
Drag-and-drop states The builder and the calendar both want them, and both need real interaction to judge. A static frame of a drag is a drawing of a feeling, not a specification.
A bottom navigation The web app never narrows to a phone. Below 1000px it is the phone app’s job, and pretending otherwise produces two mediocre designs instead of one good one each.
Toasts Nothing in this product succeeds quietly enough to need one. State changes are visible in place — a payment appears in the ledger, a nudge appears in the queue.
