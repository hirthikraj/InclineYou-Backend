Settings & the sync queue

Two screens the app spreads over eight. Settings is a form, and forms are what a desk is for. The sync queue is the one place the product’s offline-first architecture becomes visible — and on the web it gets a full screen rather than a drawer item, because a trainer at a desk is exactly the person who needs to check that yesterday landed.

SUPERSEDED · 23 Aug 2026 — the web app is ONLINE-ONLY

This page was written offline-first. That decision has been reversed for the web: the web app writes every response straight to the server — no browser storage, no write queue, no sync. Offline-first remains the architecture of the phone (app/) and of nothing else.

So wherever this page draws or argues for an offline banner, a synced / queued pill, a “held on this device” count, or the sync-queue screen, that chrome is not built on the web. The reasoning around it is kept, because the rest of each finding depends on it — only the offline half is void.

Authority: CLAUDE.md at the repo root, and web app/web/AGENTS.md. Do not re-derive the offline behaviour from this page.

Six entries are on this device and not yet on the server

This is normal and it is the architecture: everything writes locally first. The list below is every pending item with the reason it is pending — a queue you cannot inspect is a queue you cannot trust.

Nudge to Farhan Q · payment due Held — a WhatsApp send needs a connection. It will go automatically, or you can cancel it.
Order matters

The queue is ordered, not parallel. Arjun’s sets wait for Meera’s because a later edit must never land before the thing it edits. This is why one stuck item shows a second as “waiting” rather than failing it.

Synced today 31
Push A · Priya N · 11 sets Synced 07:14 · created offline 06:20
₹8,000 UPI · Meera K Synced 07:14

Every pending item with the reason it is pending. The queue is ordered, not parallel, and the interface says so — otherwise “waiting for the one above” looks like a second failure. The held WhatsApp nudge is separated from the retryable items, because “this cannot work offline” and “this has not worked yet” are different facts.
