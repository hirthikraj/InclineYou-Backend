Forms — eight components, and one rule that decides most of them

Every field here carries a visible label. That single decision removes most of the usual argument: no floating labels to animate, no placeholder doing two jobs, no guessing what a filled field was for. What is left to decide is where the unit goes, when a change takes effect, and how an error says what to do next.

SUPERSEDED · 23 Aug 2026 — the web app is ONLINE-ONLY

This page was written offline-first. That decision has been reversed for the web: the web app writes every response straight to the server — no browser storage, no write queue, no sync. Offline-first remains the architecture of the phone (app/) and of nothing else.

So wherever this page draws or argues for an offline banner, a synced / queued pill, a “held on this device” count, or the sync-queue screen, that chrome is not built on the web. The reasoning around it is kept, because the rest of each finding depends on it — only the offline half is void.

Authority: CLAUDE.md at the repo root, and web app/web/AGENTS.md. Do not re-derive the offline behaviour from this page.

Text field

Stable

A single line of text with a label above it. Every field in this product has a visible label — a placeholder that disappears when you type is a label you cannot check your answer against, and this is a product where the answer is a phone number or a rupee figure.

Do and don’t

guidelines

Do

This is how they log in.

Label above, placeholder showing the format, hint explaining the consequence. Three different jobs, three different places.

Don’t

Placeholder as label. The moment the trainer types, the field stops saying what it is — and on a form with six fields they will scroll back up to check.

Accessibility

ConcernHow it is handled
Label associationA real <label for>, so clicking the label focuses the field and a screen reader reads the two together.
Hint associationaria-describedby points at the hint and the error, so both are announced after the label.
Erroraria-invalid="true" plus text that says how to fix it. “Invalid” is not an error message.
Autofillautocomplete="tel", name, email where they apply — a trainer filling twenty-two clients should not retype their own gym name.
ContrastValue 17.0:1, label 7.9:1, hint 6.1:1, placeholder 6.1:1, border 1.9:1 — the border is decorative because the label carries the meaning.
Never placeholder-onlyFails SC 3.3.2 and SC 1.4.3 at the same time.

Dropdown

Stable2026 pass

The select’s popup, claimed. Until this pass the open list was the last piece of platform chrome left in a form: the button obeyed the stylesheet and the list was the OS’s — a white panel with a blue hover on either theme, which read as a bug beside fields this considered. It genuinely could not be styled before, because the popup lived outside CSS. Chromium’s customizable selects (appearance:base-select + ::picker(select), Chrome 135+) put it inside; everywhere else the platform popup remains — the same native control this library keeps on purpose.

Form group

Stable

The rules for putting fields together: one column, labels above, related fields in a titled section, and the primary action at the end of the panel rather than floating over it. A form in this product is usually four fields long, and the layout exists to keep it that way.

Classes .col .sect .grid2Columns 1, or 2 for short paired valuesUsed in add client, setup, settings

Rules

guidelines
RuleWhy
One columnTwo columns of fields make the eye choose a reading order, and half of readers choose wrong. The only exception is a pair that is genuinely one value — sessions × fee, floor % / remote %.
Labels above, never besideA side label costs 120px of a 420px panel and forces the field to be narrower than its content.
Group with a titled section, not a cardA card inside a panel is two borders saying the same thing. .sect is a hairline and a title.
12px between fields, 24px between sectionsThe spacing is the grouping. If two fields are 24px apart they are read as unrelated.
Actions at the end, right-aligned, primary lastThe reading order ends where the action is. A floating action bar over a four-field form is solving a scrolling problem that does not exist.
Required is the defaultOptional fields are marked (optional) in the label. Marking eight of nine fields with an asterisk tells the reader nothing.
Errors on submit, not on blurValidating a phone number after four digits tells a trainer they are wrong while they are still typing it.

Grouping<fieldset> with a <legend> for a titled section, so the group name is announced with each field inside it.
Tab orderDOM order, top to bottom. Never a tabindex above 0.
Error summaryOn submit, focus moves to the first invalid field and the count is announced. A form that scrolls silently to an error nobody heard is a dead end.
EscapeCloses the panel, once, and only if nothing was typed — otherwise it asks. Discarding typed work on a stray keystroke is unforgivable in a product used one-handed at a gym desk.
