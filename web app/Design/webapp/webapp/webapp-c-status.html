Status and identity — the six small things that carry most of the meaning

These are the components a trainer reads without knowing they are reading. The important boundary is the first one: a tag can never be clicked and a chip always can. Everything else here follows from a single constraint — nine semantic colours, and not one of them invented for the web.

SUPERSEDED · 23 Aug 2026 — the web app is ONLINE-ONLY

This page was written offline-first. That decision has been reversed for the web: the web app writes every response straight to the server — no browser storage, no write queue, no sync. Offline-first remains the architecture of the phone (app/) and of nothing else.

So wherever this page draws or argues for an offline banner, a synced / queued pill, a “held on this device” count, or the sync-queue screen, that chrome is not built on the web. The reasoning around it is kept, because the rest of each finding depends on it — only the offline half is void.

Authority: CLAUDE.md at the repo root, and web app/web/AGENTS.md. Do not re-derive the offline behaviour from this page.

Tag

Stable

A read-only label on a thing: what state it is in, or which of two worlds it belongs to. A tag is never clickable — that is the entire difference from a chip, and confusing the two is why users click things that do nothing.

Class .tagVariants 9Height 20pxInteractive neverUsed in tables, rows, panels, the calendar

Specimen

NeutralReceivedRenew soon11 days lateMovedLiveFloorRemotePR

Variants

Nine, and not one of them is a new colour — they are the app’s semantic and domain tokens doing the same jobs they already do on the phone. The floor / remote pair works harder here than on mobile, because a week grid shows twenty-three sessions at once and colour is the only way to read it at a glance.

A pressable pill. Two jobs: a filter that narrows the list below it, and a token that shows something already chosen and can be removed. Both are interactive, which is the line between a chip and a tag.

The copy matters more than the colour here. Offline in this product does not mean “broken” — it means the queue is doing its job, and the pill is worded so a trainer never stops mid-set to worry about it.

Toast

Stable2026 pass

The confirm with no row to land on. This product answers a write on the row it changed — the roster row is the receipt, and that stays the rule — so the toast is the LAST resort, not the first: a save that navigates away, an export that finished, an undo window. Bottom-right, one at a time, one action at most. Anatomy follows the pattern sonner standardised across the 2026 React ecosystem.

Class .toastVariants 4Width 340pxInteractive dismiss, one actionMaterial glass under §24

Specimen

Payment recorded. ₹2,000 · Meera K · UPI
Session moved to Thu 6:00 am.
Export failed. The server did not answer — the file was not written.

Behaviour

One on screen; a second REPLACES the first rather than stacking a column of history. Six seconds, paused while hovered; a danger toast stays until dismissed, because a failure that removes itself was never shown. The action is one verb — Undo, Retry, Open — never a second sentence. A toast never carries a field error: the field does (.fld__e), where the fix is.

Accessibility

ConcernHow it is handled
Announcementrole="status" (polite); a danger toast is role="alert". Focus is never stolen.
Dismiss targetThe 20px × sits in a 32px slop target, same mechanism as the chip.
Reduced motionThe rise is a keyframe, so prefers-reduced-motion removes it wholesale.
Reduced transparencyGlass falls back to solid --tx-surface, per §24.

Skeleton

Stable2026 pass

The shape of the screen before its data. The --tx-skeleton token had existed since v1 of the stylesheet with NOTHING using it — every screen went from blank to full in one paint. Shapes mirror the content they stand for, which is the entire case for a skeleton over a spinner: the reader builds the page’s map before the data lands, and the wait reads shorter. The 2026 guidance is unambiguous: skeletons for structured content, spinners for single actions, and nothing at all under ~300ms.

Class .skelVariants 6Motion 1.6s shimmerInteractive neverUsed in lists, tiles, the ledger

Specimen

Rules

The skeleton is drawn from the REAL layout — same row height, same avatar size, same tile radius — so nothing jumps when the data arrives. Two rows stand for a list of any length; a wall of twenty shimmering rows is louder than the content it replaces. The container carries aria-busy="true" and every .skel is aria-hidden; under prefers-reduced-motion the shimmer stops and the shape stays.

Tooltip

Stable2026 pass

The name of a control that dropped its label. The rail always had a private one (it is the collapsed rail’s only label, and it lives in the top layer for the clipping reasons documented at §03); every OTHER icon button in the product pointed at nothing. Inverse fill — ink on the opposite ground — so it holds maximum contrast in both themes without a new token.

Class .tipVariants 1 + kbd slotDelay ~300ms in, none outInteractive never — pointer-events:none

Specimen

Record paymentPCopy planArchive

Shown static on the bench; in the app it is positioned against its control and appears after a beat, so a pointer travelling across a toolbar does not fire six of them.
