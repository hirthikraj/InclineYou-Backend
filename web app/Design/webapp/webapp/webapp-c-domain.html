Domain — the four components that only make sense in this product

A generic library would stop at the previous page. These four are where the product actually lives: a session block that encodes whether the gym takes a cut, a builder cell whose grid runs across the week, a set row that is the one genuinely phone-first thing here, and the rules for money — which is the subject of the whole app and therefore the least negotiable.

Session block

Stable

One scheduled session, drawn in the week grid. It carries four facts in about 110 px: when, who, what plan, and whether it is a floor or a remote session — the last one by colour, because a week grid shows twenty-three of these at once and colour is the only thing readable at a glance.

Accessibility

ConcernHow it is handled
Grid patternThe week is a role="grid"; each block is a gridcell whose accessible name is the whole sentence: “Tuesday 6am, Meera Krishnan, Push A, floor session, done”.
Never colour-onlyFloor and remote are also words in the block’s accessible name and in the session panel. The grid is usable in greyscale.
ConflictCarries a warning glyph and the word “conflict”, not just hatching.
KeyboardArrow keys move by cell, ↵ opens the session panel. Moving a session by keyboard uses cut and paste on the row menu, because drag alone would fail SC 2.5.7.
ContrastFloor 8.4:1, remote 7.6:1, done 5.9:1, no-show 5.1:1 on their own washes.

Set row

Stable

Money figure

Stable

Not a component so much as a rule with teeth: every rupee figure in this product is tabular, right-aligned, and carries where it came from. A solo trainer’s income is the subject of the whole app, and a number they cannot check is a number they will not trust.
