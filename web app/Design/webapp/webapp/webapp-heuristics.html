Heuristic audit — Nielsen’s ten, against every screen from auth to portal

140 findings across the ten heuristics. 56 hold, 65 were fixed, and 19 are open and named. (Counted off the tables rather than kept by hand: the previous header said 47 fixed and 18 open where the rows said 46 and 19, which is what a hand-maintained total does.) An audit where everything passes is an audit that was not run — the useful rows here are the ones that failed, including one where a component was quietly contradicting its own reason for existing.

Ninety-seven of them are re-runs, against work built after this file was written. Seventeen marked Second pass cover the rail and the schedule; eleven marked Third pass cover the month view — including the one that found every weekday label in the set to be a day out; twelve marked Fourth pass cover the booking form, which existed as nineteen live controls and no screen; and twelve marked Fifth pass cover the hours editor, the table every grid in the set had been reading and none could write. Four of them correct rows in this file that the new work falsified, two contradict rows that still say Holds, one is a bug in shipped code rather than a gap in a drawing, and one is this design set breaking the single rule its own stylesheet opens with — which is the point of re-running an audit rather than filing it.

Ten marked Eighth pass cover the roster and the client file, and they are the first set in this file where most of the findings are in shipped code rather than in a drawing. Eight of the seventeen corrections that pass produced are defects in app/src/clients/ — two attention models that disagree about who needs the trainer, a seven-boolean array that cannot tell a rest day from a missed one, a chart that plots the reading its own list marks replaced, a group header that counts rows it does not contain, and a hard-coded pronoun. None of them breaks a build or fails a type check, and none of them was findable by reading the file that described the screen.

Five marked Ninth pass are a different kind of row again: not findings but closures. Two of the eighth pass’s open items are now changes in shipped code — the sparkline that plotted a reading its own list called a mistake, and the 59 tabs that announced themselves correctly and could not be focused — and the third is the largest single correction in this file: the two attention models that had been answering “who needs the trainer” differently on two screens are now one exported table with one order. The other two closed the pair the sign-in file was blocked on, and neither was waiting on a decision this set could make: one moved the UPI risk to the first collection, where the money actually moves, and the other stopped shipping a fallback that switched itself off when its environment variable was absent. Every item that carried a Blocking tag anywhere in this set is now closed.

Ten marked Tenth pass cover the workout console, which had drawn one frame for the twelve surfaces the app ships. Eight of the ten are fixes, and the through-line is that this screen states more rules than any other in the product — sixteen of them — and the one frame had broken the one the spec names as most at risk: it put the client’s package in the session summary, where the rule is that finishing a log never moves it. The two that stay open are both in log.ts: a type that cannot express a rule the same repository states, and a field that counts sets, says sessions, and is read by nobody.

SUPERSEDED · 23 Aug 2026 — the web app is ONLINE-ONLY

This page was written offline-first. That decision has been reversed for the web: the web app writes every response straight to the server — no browser storage, no write queue, no sync. Offline-first remains the architecture of the phone (app/) and of nothing else.

So wherever this page draws or argues for an offline banner, a synced / queued pill, a “held on this device” count, or the sync-queue screen, that chrome is not built on the web. The reasoning around it is kept, because the rest of each finding depends on it — only the offline half is void.

Authority: CLAUDE.md at the repo root, and web app/web/AGENTS.md. Do not re-derive the offline behaviour from this page.

The ten worth reading first

1 · The panel was undoing its own argument. A panel exists so the ledger behind it stays readable. Measured on a real render, the scrim behind it dropped that ledger to 1.8:1. Fixed to 26%, now 6.4:1.
2 · Six of seven panels had no scrim at all, so nothing signalled an active layer. Fixed.
3 · Moving a session had no undo, and a move tells the client automatically. The house rule — ten seconds, in place, on the row that changed — was written in H03 of this file and the schedule was exempting itself from it. Fixed by holding the message for the ten seconds, because undo after the WhatsApp has gone is an apology.
4 · Every weekday label in the set was a day out. Nine files said Mon 11 August 2026; 11 August 2026 is a Tuesday. It survived because no view had to agree with another about which weekday a number was — the month grid was the first that could not hold both mappings, and it fell out immediately. And one file survived the fix. Today still said Tuesday 12 August in four places — 12 August 2026 is a Wednesday — on the one screen whose entire subject is a date. It now imports the day from gen_schedule and asserts it.
5 · A shipped function generates bookings into the trainer’s own holiday. occurrencesFor in diary.ts takes a start, some weekdays and a count, and never looks at time_blocks — which is exactly the behaviour the booking section criticises Google Calendar and Vagaro for. Found by drawing the web form, which refuses the date; the phone does not. This is the only finding in this file that is wrong in code someone can run today.
6 · We broke the one rule this stylesheet opens with. The band being edited in the hours editor filled with --tx-accent. A four-hour window is 240px tall and has the day's sessions inside it, so a solid lime ground turned them into dark-on-lime mush and swallowed the danger ring on a session the frame existed to point at. Lime is a fill, never a ground for content. Selection moved to a 2px edge. Caught on a screenshot, not by reading the CSS — which is the argument for rendering every frame.
7 · The trainer’s headline figure was under the wrong word, and the arithmetic closed anyway. Today led with ₹1,06,500 labelled Billed this month. That is the month’s collected figure; billed is ₹1,24,500 — so Yours, the one number this product exists to compute, read ₹57,500 where the app computes ₹75,500. It survived four passes because two of the money file’s figures collide by accident: collected equals floor billing and pending equals remote billing, so the wrong base produced a subtraction that closed. Both collisions are now asserted in the generator.
8 · The most dangerous control on the deck was its easiest one. Today’s queue put six one-click buttons on the screen and four of them sent a real WhatsApp to a real client about money, with no way back. The phone never had the problem — its list navigates to the client and its code says so in a comment — so this was the cost of a deliberate web promotion, committing in place so that triaging six rows does not mean six round trips, and the cost had not been paid. Fixed by holding the sending, in the row, with the countdown as the receipt; and the hold attaches to the verb, so Renew stays instant because it tells nobody. It was the only blocking finding of the sixth pass and it is closed.
9 · A design file documented an onboarding flow that does not exist. Getting in specified six setup steps — name and business, where you train, the gym’s share, how you get paid, your first clients, reminders. SETUP_STEPS in the app is eight, and not one of the six was one of the eight. Not renamed — absent. Found the first time that file was checked against the code rather than against the file before it, which is the argument for importing a list instead of retyping it: the eight steps, their labels, their answer sets and the completion weights are now read from four modules that ship.
10 · Five open items are blocking, not cosmetic: the builder has no undo stack, moving an exercise has no keyboard path, item 13 above, and items 18 and 19 — every fallback channel into the product is unbuilt, and a UPI typo has a price. The first two are why builder cell is still marked Beta.

Method. Heuristic names and definitions are Jakob Nielsen’s ten, as published by Nielsen Norman Group. Contrast and overflow figures come from a Playwright audit that composites real backgrounds and, for the glass surfaces, samples actual rendered pixels rather than computed styles. Every “Fixed” row above corresponds to a change in assets/webapp.css or a builder in this pass. The second-pass rows were evaluated against webapp-rail.html and webapp-schedule.html and their generators, gen_rail.py and gen_schedule.py; the contrast figure quoted in H05 (white on --tx-danger at 3.06:1 in the dark theme, which is why that chip does not use it) was sampled from a headless render rather than computed from tokens. The fourth-pass rows were evaluated against the booking form in gen_schedule.py and against app/src/screens/main/diary/BookSheet.tsx and app/src/diary/diary.ts — the claims about all.slice(0, 6), about buildDay composing items from input.sessions alone, and about commitBooking checking only result.at before bookSeries batch-creates the rest are all readable in those files. Their competitor comparisons trace to Google Calendar’s Create a recurring event help page, Vagaro’s Schedule Repeating Appointments, ABC Trainerize’s How to Schedule Appointments on the Web, and Nielsen Norman’s EAS Framework for Simplifying Forms. The 4.9:1 figure for the disabled primary was sampled from a headless render of frame 4a, not computed. The fifth-pass rows were evaluated against the hours editor in the same generator and against app/src/screens/main/diary/WorkingHoursScreen.tsx, whose header comment is the source for the two-layers-not-four decision, for the picture-first sheet, and for the rule that a save stranding nobody goes through without a dialog. Their competitor rows trace to Calendly’s How to set your availability (List view, Calendar view, and the Edit date / Edit all Mondays choice) and to Acuity’s availability and troubleshooting articles for the fact that its only out-of-hours warning fires at booking time. Neither help centre documents a conflict alert while a schedule is being edited.

What a heuristic walkthrough did not find. Worth recording: the first pass of this audit returned Holds for the schedule and did not notice that all 102 sessions in it were 42px tall, or that 494 elements on it were unreachable by keyboard. Neither is a heuristic violation you meet by walking the ten — “a trainer's sessions are not all sixty minutes” is a domain fact. The ten are a net with a known mesh size, and they are not a substitute for reading the data model.
