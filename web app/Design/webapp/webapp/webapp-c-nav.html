Navigation — eight components, and one deletion

The structural difference between this and the app is that nothing here has to be opened. The phone’s navigation drawer — a whole screen with seven destinations — does not appear in this library at all: it became the rail, which is furniture. What the web adds instead is a palette and a bulk bar, neither of which has any phone equivalent.

SUPERSEDED · 23 Aug 2026 — the web app is ONLINE-ONLY

This page was written offline-first. That decision has been reversed for the web: the web app writes every response straight to the server — no browser storage, no write queue, no sync. Offline-first remains the architecture of the phone (app/) and of nothing else.

So wherever this page draws or argues for an offline banner, a synced / queued pill, a “held on this device” count, or the sync-queue screen, that chrome is not built on the web. The reasoning around it is kept, because the rest of each finding depends on it — only the offline half is void.

Authority: CLAUDE.md at the repo root, and web app/web/AGENTS.md. Do not re-derive the offline behaviour from this page.

Do and don’t

guidelines

Do

Money3

A lime bar and lime text on a 12% wash. Legible on dark and on light, and the current destination is unmistakable.

Don’t

Money3

A filled lime row. It looks fine here and it is fine here — but the same rule applied on light theme puts 13.5px text on #C6F24E at 1.3:1. The rail item is the one component where this decision was made once, deliberately.

Accessibility

ConcernHow it is handled
LandmarkA <nav> with aria-label="Sections", so it can be jumped to and skipped.
Currentaria-current="page" on exactly one item. Not aria-selected — these are links, not options.
GroupsEach group is a <ul> with an accessible name from its kicker, so “BUSINESS, 3 items” is announced before Money.
CountsIncluded in the link’s accessible name: “Money, 3 overdue”.
KeyboardG then a letter jumps to a destination without touching the rail at all — the rail is for the eye, the shortcut is for the hands.
CollapsedAt 64px the labels are visually hidden but still the accessible name; the glyph never becomes the name.

The rule that makes it useful

guidelines
RuleWhy
Actions are scoped to the current match, not globalTyping mee then arrowing down offers Record a payment for Meera. A flat list of every action in the product is a menu, and menus are slower than clicking.
Results are grouped and the groups are namedClients, actions, destinations, exercises. Four short groups beat twenty undifferentiated rows.
It shows the shortcut it replacesG S beside Schedule teaches the faster path while being used.
The trigger is a real buttonA decorative box that only responds to ⌘K is invisible to everyone who does not already know the product.
It never performs a destructive action directlyArchive from the palette opens the confirm, same as anywhere.

Bulk bar

Stable

What the toolbar becomes when rows are selected. It is the visible half of the single most valuable thing the web app has that the phone does not: doing one thing to many people at once. Every label carries the count, so nobody guesses how many they are about to nudge.

Class .bulkReplaces the toolbar, in placeUsed in roster, ledger, sessions, adherence

Specimen

3 clients selected

Rules

guidelines
RuleWhy
Replaces the toolbar in place; never floatsA floating bar covers the rows it is about to act on. The one thing a trainer needs to see while bulk-nudging is which three people.
Every label carries the countNudge all 3, not Nudge. The count is the fact that matters and the thing a mis-selection changes.
Only actions that make sense for manyNudge, mark paid, reschedule, export, archive. Not Edit — there is no sensible bulk edit of three different people.
Destructive actions still confirm, and name the count“Archive 3 clients?” with all three named in the body.
Esc clears the selectionAnd the toolbar returns. One key, one layer.
The header checkbox is mixed, never a third valueIt reports the state of the rows; it is not an option a trainer picks.
