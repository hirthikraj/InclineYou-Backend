Train X Design System

Everything below is a token. No component hard-codes a colour, size or radius — swap the :root block and the whole app reskins. Built for the Command Deck direction: an instrument panel a trainer can read at arm's length in a dim gym, at 8pt radius so it doesn't fight Material 3 on Android. Dark is the default theme; light is a complete pair, not an afterthought. Toggle it top-right — every specimen on this page is live.

Foundations · 01

Colour

One brand accent. Everything else is either a surface, an ink, or a meaning. The single most important rule here: the lime is a fill colour, not a text colour. #C6F24E on white is roughly 1.3 : 1 — invisible. So the fill stays identical in both themes to protect the brand, and a separate --tx-accent-text token darkens to #4F6B0A in light mode for links, active tabs and small icons.

Components · 12

Inputs & forms

Rebuilt from a survey of what Linear, Radix, Primer, shadcn/ui, Geist, Stripe, Polaris, Notion, Raycast, Revolut and Wise ship today. Four things changed from the first draft, and each one is a documented dating signal: uppercase letterspaced labels (no current system uses them), a hard mid-grey border on white, a native <select> with a CSS triangle, and error text that shoves the form down when it appears.

The box lives on .tx-control, never on the <input>. That single decision is what lets one field hold a country chip, a leading icon, a unit affix and a clear button and still show one focus ring.

Focus uses outline: 2px solid; outline-offset: -1px — the outline sits on top of the hairline, inside the box. Radix and Primer converged on this independently: no layout shift, no bleed into the field below, and it respects the corner radius. Pair it with a 3px translucent halo.
Validate on blur, clear the error on input. Two studies (n=77, n=90) found users make measurably more errors when validation fires the instant they leave a field.
Transition all. Only box-shadow, background and color animate — transitioning all animates width and height during layout and produces the jelly effect that reads as amateur instantly.

12.4 · Affixes — icon, unit, clear

Money in a form: type="text" + inputmode="decimal", symbol as an affix outside the value, numerals right-aligned and tabular. Format on blur, strip on focus — inserting separators mid-typing jumps the caret.
Use type="number" for money. Spinners, rejected thousands separators, and inconsistent decimal handling across locales.

12.5 · Phone — fused country segment

The country chip is fused into the left edge — same height, same fill, a 1px divider between — so :focus-within gives the whole group one ring. Tapping it opens a searchable bottom sheet, never a 200-item native select.

12.6 · Select — trigger plus bottom sheet

What the trigger opens
Payment mode
The trigger is styled as a field, not a button — same height, radius, fill and hairline — so a form reads as one rhythm. Trailing chevron is a real 18px glyph at ink-3.
Ship a native <select> with a CSS-triangle arrow. It's the single loudest dated tell in a mobile form: no search, no secondary text, unstyleable rows, and an iOS wheel picker that is slow past about eight options.

12.7 · Verification code

One real transparent input under six presentational slots — not six inputs. Select-all, paste, cut and autofill then work as single operations. The caret on the active slot is a div; the real caret is invisible.
type="text" inputmode="numeric" autocomplete="one-time-code" pattern="\d{6}", and end the SMS with @trainx.app #481234 so iOS and Android offer the code above the keyboard.

12.8 · Search

Search is filled and pill-shaped; form fields are outlined. That contrast is deliberate and near-universal now — it tells you at a glance which control filters and which one collects. type="search" also turns the iOS return key into Search.

12.9 · Stepper

The value is directly editable — nobody taps + twenty times to reach 60 kg. Buttons 56×56 and pushed to opposite ends, with the value acting as the spacer, so a thumb can't mis-hit.
Reps step by 1, load by 2.5 kg. Long-press repeats and accelerates after ~500ms, with a haptic tick per increment and a heavier one at the limit.

12.10 · Textarea

Auto-grows from 3 rows to about 8, then scrolls internally. No resize handle on touch. Show the counter only past 80% of the limit, and warn rather than hard-truncate mid-word.

12.11 · Date & time

Both open a bottom sheet: a month grid with ≥44px cells, or a snapping time list. Use the native picker only where a plain date is all you need — it's free localisation and a documented WCAG target-size exception.

12.12 · Segmented & choice cards

Segmented for 2–4 short, symmetrical options. Choice cards when each option needs a sentence of explanation — anything more than that is a select.

12.13 · Amount entry — a screen, not a field

Wise ships this as a separate component from its in-form money field, and that split is right. When the amount is the task — collecting a payment, setting a pack price — it gets a hero numeral and a custom keypad, not a 52px box.

Onboarding & profile

Nine components added for the trainer setup flow. They exist because a multi-step profile flow has its own grammar — progress, skip, selection, and a completion loop — and none of it was in the system.

24.1 · Step progress

3 / 6
Segmented bar, 4px tall, 5px gap, current step half-filled. Dots read as a swipeable carousel and numbered steppers don't fit past four labels at 360dp.
Show the total. Multi-step forms convert ~14% better than one long form, and ~27% better with a visible progress indicator — the effect comes from knowing how much is left.

24.2 · Skip

2 / 3
Top-right in the app bar, 44px target, ink-3. “Skip for now” — “for now” signals reversibility, which is the actual anxiety.
Put skip next to the primary CTA at the bottom. That's where thumb momentum lives — you'll get accidental skips that look like intent.
Use “Not now” or “Maybe later”. Both are the standard notification-nag and rating-prompt wording; users have learned to distrust them.
Mark optional steps explicitly. Only 6% of mobile forms mark optional fields, and ambiguity — not effort — is what stalls people.

Initials render from the first keystroke of the name field, so the avatar is never empty — which quietly removes the pressure to upload anything.

Applying it · 28

Platform — Android & iOS

Everything before this chapter is one spec for both platforms. This chapter is the short list of places where insisting on one spec would be a mistake, and what to build instead on each side. Verified against Android 16 (API 36) and iOS 26, August 2026.

The principle: the design is shared — tokens, spacing, radius, type, iconography, information architecture, copy. The interaction grammar belongs to the platform. A user should recognise Train X on either phone and never feel it was ported.

27.1 · The shared contract — this never forks

SharedNote

Type scale and weightsInter bundled on both, so the scale holds. Line heights need per-platform overrides — see 27.6.

27.2 · Width — the number that actually bites

These mockups are drawn at 390pt (iPhone 14/15/16). Most Android phones in India report 360dp — an 8% narrower canvas for the same content. That is where a dense design breaks first, so it is the first thing to test.

Finding at 360dpVerdict
Top tabs — 4 tabs overflowed the rowFixed. .tx-tabs now scrolls horizontally. On Compose use a ScrollableTabRow, not TabRow.
Session-row secondary line truncates earlierBy design — it ellipsises. But it confirms the row is at its density limit; don't add a fourth element to it.
Stat rail, live card, set table, money cardAll hold at 360 with no change.
Everything elseNo overflow.
Design at 360, verify at 390 — not the other way round. Anything built to fit an iPhone first will need surgery to fit the phone most of your users own.
Android text scales with the user's font setting and there is no clamp — no equivalent of iOS's dynamicTypeSize(…). Android 14+ also applies non-linear scaling above 200%, so 2× the sp value is not 2× the rendered size. Test the roster and the set table at maximum font scale; that is where a design of this density fails.

27.3 · The seven divergences

#ConcernAndroidiOS
1Press feedback Ripple. ripple() from material3 — rememberRipple() is deprecated. Ripple encodes where you touched; a flat opacity change throws that away on large targets. Opacity/scale. Our :active background shift is the iOS model.
2Transient message + undo Snackbar, via Scaffold(snackbarHost = …) so it clears the tab bar and the nav-bar inset automatically. One at a time; a new one dismisses the previous. Don't publish millisecond durations — use SnackbarDuration.Short/Long/Indefinite. Toast is discouraged in-app and now draws your app icon on API 31+. No system snackbar exists. Build the toast component in this system as a custom overlay above the tab bar, honouring the safe-area inset. .alert is wrong for undo — it's modal.
3Back affordance System back is always present. Show an up arrow in the app bar only when the screen is not a tab root — Android's own principle is "the Up button never exits your app". Use Icons.AutoMirrored.Filled.ArrowBack so it flips for RTL. A visible back chevron on every pushed screen. The swipe-from-edge gesture is an accelerator, not the affordance — it's invisible and unavailable to Switch Control. Sheets use Close/Done instead.
4System bars Edge-to-edge is mandatory at target SDK 35+, and API 36 removed the opt-out entirely. Consume WindowInsets.safeDrawing; Scaffold does most of it. Handle gesture nav and 3-button nav — they occupy different heights. Safe-area insets only. The home indicator area is already in our tab-bar spec.
5Predictive back Default-on at API 36; onBackPressed() is no longer called. Material's own sheets and drawers animate for free — our custom sheets do not. Wrap them in PredictiveBackHandler, drive the animation from BackEventCompat.progress, and rethrow on cancellation. No equivalent. Sheet dismissal is the drag gesture.
6Date & time pickers Modal, two-step: pick then confirm. Has a first-class typed-entry mode (DisplayMode.Input, TimeInput) — keep it, trainers type faster than they scroll. Note there is no TimePickerDialog; you compose one. Inline and one-step — the binding updates as the user scrolls. Plan for no confirm button. .wheel stays the fastest for time.
7Dialogs You position: dismiss at the start, confirm at the end, destructive tinted error. You declare: Button(role: .cancel / .destructive / .confirm) and the system orders them. Labels are text-only — icons are silently dropped.
Write the dialog spec in terms of roles, never positions. Android honours position; iOS overrides it. Roles are the only thing both platforms respect.

27.6 · Three things not to believe

"Material 3 Expressive is stable." As of July 2026 stable material3 is 1.4.0 and the Expressive set is not in it — it's in the 1.5.0-alpha line. Individual APIs were promoted out of experimental within an alpha library, which is not the same thing. Build on stable 1.4 and treat Expressive as opt-in later.
"Liquid Glass is the new look, put it everywhere." Glass belongs to the navigation layer — toolbars, tab bars, floating controls. Apple is explicit that it should never be applied to content. Our cards, rows and fields are content. Glass on a set table would be a platform error, not a modernisation.
"Use RoundedRectangle(cornerRadius: .containerConcentric)." That's a UIKit spelling and doesn't exist in SwiftUI. The SwiftUI API is ConcentricRectangle / .rect(corners: .concentric(minimum:)), iOS 26+. Relevant to us because nesting a chip inside a field inside a card should derive its radius from the parent, not repeat it.

27.8 · Build order

Android first. India is where Train X ships, Android is the volume, and this system is already tuned for it — 8pt radius chosen so it doesn't fight Material 3, 48dp tap floor, Inter bundled. Building iOS first tends to bake in assumptions (390pt width, no ripple, no system back, no font-scale ceiling) that are expensive to unpick.
Override MaterialTheme's colour scheme wholesale rather than mapping our tokens onto Material's roles. Our surface ladder and Material's tonal elevation model are different systems; half-mapping produces a UI that is neither.
Do the colour QA on a ₹12–15k Android LCD, not a MacBook. Saturated lime is the one token here that can look sickly on a poor panel — if it does, drop to #BCE548 and re-run the contrast check.
